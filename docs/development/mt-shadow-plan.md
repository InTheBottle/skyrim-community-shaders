## 1. Threading model: per-shadow-map fan-out, replica-path record, ordered replay

**Chosen unit of work = one shadow map** (one `RenderShadowmap` 0x141305610 invocation = one `{DSV-target, slice}`: a sun cascade, a VL slice, a focus slice, or a local-light face). This is candidate **#1's granularity**, hardened with **#3's materialized record→replay seam and private scratch atlas**, and with **#2's engine-remainder partition + cost-weighting grafted as a later refinement**. Candidate #2's flat pass-tape is explicitly rejected as the primary model and demoted to a phase-4 option.

### Why map granularity is the right seam for *this* race surface

The phase-1 race surface (the four analyses) is dominated by fixed-address process globals: the `0x5D8` `RendererShadowState` dirty block at `0x143027EB0`, the technique/shader/material caches (`0x1403283BA4/A8`, `0x143490BB0`), the dyn-VB (`0x143025F18[0..2]` + state `0x143025F30`) and bone-CB (`0x143027A00`) rings, and the single immediate-context pointer `0x143027EA0`. Map granularity is the seam that lets us **sidestep every one of them concurrently** instead of fighting them:

- **Disjoint DSV slices → no inter-map data dependency.** Maps write non-aliasing atlas regions, so N maps recorded in parallel and replayed in engine-call order reproduce vanilla's serial submission bit-for-bit. There is nothing to synchronize between workers.
- **Per-map partition preserves the engine's exact intra-map pass order *and* its change-detection caching.** A `BSShader`'s `SetupTechnique`/`RestoreTechnique` pair and the technique/material cache transitions all live inside one map on one worker, so the replica's per-worker caches see the identical hit/miss sequence the engine saw. This is what keeps **byte-identical** command streams — the property #2 sacrifices at every chunk boundary (a chunk split forces a redundant `BeginPass`, so #2 can only ever be validated with a *tolerant* order-equivalence check, never the strict `DiffWindows` tuple identity we already trust to 1.1M/0).
- **The fixed-global reads are dodged, not raced.** Workers run **only CS replica code** (`ReplicaRenderPassImmediately` → `DrawTriShapeReplica`) against a **private `WorkerState`** and issue on a **private deferred context**. They never call the engine helpers that hard-code `0x143027EB0` etc. The one engine helper the replica still `EngineCall`s in the hot path — `SetDirtyStates` (0x140D705B0) — is **re-implemented in CS against the worker's private dirty block** (fully documented in the dossier; it is the keystone RE item, section 3c).

### The central new component: a standalone per-map replica driver

The decisive design realization: **map SETUP is cheap and O(maps); caster PASS recording is expensive and O(casters).** So we split them:

- **Map setup stays serial on the render thread** — the deterministic lazy pool-slice allocation (free-slice bitmask `dword_141E10538`, done in the per-light loops `0x141324C30`/`0x14132D040`/`0x14132E4E0` *before* `RenderShadowmap`), the per-map viewport, the depth-target/slice binding, and the per-map shadow view-projection CB. None of these ever race because they never leave the render thread. This is candidate **#1's "planning interceptor"**, and it is why #1 is `high` effort while #2/#3 are `very-high`.
- **Caster recording is parallelized** — each worker replays its map's casters into an `ID3D11CommandList` on a private deferred context.

The keystone deliverable is therefore a **standalone per-map replica driver** (`ShadowMapReplay::RenderMap(MapWork&, WorkerState&)`) that, given a by-value snapshot of a map's setup and a private worker state, reproduces the whole map. It is needed **both** by the threaded path **and** by the output validator (which must render the replica's version of a map to a scratch atlas to diff depth). Building it once, single-threaded, and proving it map-identical to vanilla is Gate G1; parallelizing it across N private contexts is Gates G3–G4. Everything hangs off this one component.

### Fan-out / ordering / execution

1. **Collect (serial, render thread).** Detour the driver `DrawWorld::RenderShadowmaps` 0x1412E3480 (as `ShadowDeferred` already does). Inside, detour `RenderShadowmap` 0x141305610 as a planning interceptor that captures, **by value**, one `MapWork{ camera=desc+64, accumulator=desc+72, targetRTV, slice=desc+88, viewport, renderFlags=a4, cameraCBBytes }` per map into an ordered `mapWorkList` (call order == canonical replay order; by-value because directional reuses `desc[i]` and rewrites `+84` between the VL and main loops). The engine's per-light loops still run to perform slice allocation deterministically.
2. **Partition.** Split `mapWorkList` into *fully-coverable* maps (every pass passes `CanReplicate`) → worker pool, and *has-uncoverable* maps → **engine remainder** rendered serially on the immediate context at their canonical positions (candidate #2's remainder idea, applied at map granularity so we never mix replica/engine work on one private context mid-map). Later (phase 4), a map may be split at gap boundaries into command-list *segments* for finer coverage.
3. **Record (parallel).** `T` workers from the existing bshoshany `BS::thread_pool` (the one `ParallelShaderSetup` already owns, `ParallelShaderSetup.h`), each owning a private deferred context created once at `Setup`, replay their assigned maps via `ShadowMapReplay::RenderMap` and `FinishCommandList(FALSE)`.
4. **Barrier + ordered replay (serial).** Render thread `wait_for_tasks()`, then `ExecuteCommandList(cl[m], FALSE)` in **`mapWorkList` order** (not completion order), interleaving engine-remainder maps at their positions. Re-establish the immediate context exactly as `ShadowDeferred.cpp:332-373` already does (re-apply standalone bindings + saved viewport/scissor + `sflags[0]=0xFFFFFFFF`).

`T = clamp(hardware_concurrency − RESERVE, 2, CAP)`, `RESERVE≈4` (render + DXVK submit/CS + present + sim), `CAP≈6` (the serial `ExecuteCommandList` + re-establish tail is the Amdahl limit). Ship `T=2` first. **Per the FPS memory: the record win is only realized where the render thread is the bottleneck; under the paced DLSS-G regime it may not be. Parity is the deliverable; perf is measured with the `rtprof` harness before every widening, never assumed.**

## 2. Validation layer (hard requirement) — two levels, per-map, rerunnable, N=1 first

The validator is the same component at N=1 (proves *replica-map == engine-map*) and N>1 (proves *threaded == vanilla*), unchanged. It has a **structural** half (reuse the proven 1.1M-pass machinery) and the **output** half that does not exist today.

### Level 1 — STRUCTURAL (command-stream) parity — reuse `DiffWindows`

Reuse verbatim: the 20-slot immediate-context recorder, the normalized `RecordedCall{kind,slot,a,b,c}` tuples + FNV `kMapDiscardData` byte-hashes, the symmetric CS-injection filter (`EngineCaller(_ReturnAddress())`, cpp:117), the out-of-module stub (`BuildEngineCallStub` cpp:62), and `DiffWindows` (cpp:1002) with its per-class buckets, `firstDiff` pinpoint, 64-row side-by-side dump, and rolling stats.

Generalizations required:
- **Per-map, per-pass keying.** The `RenderShadowmap` interceptor brackets each map; within a map the recorder pushes a pass-boundary marker as each `BSRenderPass` begins, yielding one window per `(mapId, passIndexWithinMap, passIdentity = geometry ptr + technique + passEnum)`.
- **Ground truth via same-frame scratch re-render (not two frames).** In `VALIDATE` mode, per frame: (1) the engine renders shadows normally to the **real** atlas on the immediate context — recorder captures the per-map **engine** windows (ground truth); (2) `ShadowMapReplay` re-renders the same maps via the replica to a **private scratch atlas** — recorder captures the per-map **replica** windows. Same frame ⇒ identical culled caster lists ⇒ **runs in motion** (satisfies the memory rule that stills never validate shadow changes), and no snapshot/restore of the immediate context is needed because the replica targets scratch. For each `(mapId, passIndex)`, call the existing `DiffWindows` over `{engineWindow, replicaWindow}`.
- **Chunk/map-boundary normalization.** A map's first pass starts from a forced-dirty cold context (the worker context is default-state), so the *engine* ground-truth window for a map's first pass must be recorded from a matching forced-dirty start, else it legitimately emits extra re-establish binds and false-diffs. Model this in the golden capture (force `sflags[0]=0xFFFFFFFF` before the first pass of each map in the engine window too).
- **Thread_local recorder for N>1.** `g_sink`, `g_filterCs`, `g_openMaps[8]`, and the stub slot become `thread_local` / per-worker (the cpp:57 note "one slot suffices" holds *only* single-threaded). `DiffWindows`' `firstDiff` line is extended to print `mapId / worker / chunk / passIndex / callIndex / field`.

This is the **order-equivalence proof**: the concatenation of the N worker windows, in submit order, equals the engine's serial per-pass stream.

### Level 2 — OUTPUT (readback) parity — the missing half

Structural + data-hash equality *implies* identical output only under deterministic rasterization; it cannot see `ExecuteCommandList` interleave or GPU-side order effects. Add whole-atlas readback:

- **Scratch atlas.** Allocate a private depth atlas matching the engine's shadow atlas format/dims. `ShadowMapReplay` renders each map to its scratch slice (depth is idempotent, so double-render is harmless — the same property compare mode already relies on, header cpp:37-41).
- **Per-map depth diff.** After the scope, `CopyResource`/`CopySubresourceRegion` both the scratch and the real atlas to a **staging** texture, `Map`, and per-slice per-texel `max|Δdepth|` + tile-hash. Per-slice granularity attributes any delta to **which map == which worker**. Report `{mapId, maxAbsDepthDelta, firstDivergentTexel, tileMismatchCount}`.
- **Production `REPLACE` skips readback** (it is a GPU sync point); output diff is `VALIDATE`-only and is a gate, not a live check. Live regression detection stays structural.

### Pinpointing which pass deviates + RenderDoc bridge

- Structural firstDiff → exact `(mapId, worker, passIndex, callIndex, field, engine-tuple vs threaded-tuple, technique, class)`.
- Output delta → `(mapId/cascade/light region, firstDivergentTexel, maxΔ)`; the map's ordered accumulator walk maps the texel back to candidate writing passes.
- **Upgrade `communityshaders.capture`** (`DevBenchBridge.cpp:500`, currently fire-and-forget) to **auto-trigger** a RenderDoc capture on any Level-1 or Level-2 divergence, tagged with the pinpoint and writing the diverging `{mapId,worker,passIndex}` to a sidecar — turning today's manual one-off frozen-scene A/B into an automatically addressed capture.

### How it is invoked / reran, and how a future broken pass is caught

- **Headless REST surface.** Extend `BuildUtilReResult` (or add `BuildShadowValidateResult` for a `communityshaders.shadowvalidate` tool) to return `{ passesCompared, passesDiverged, divergedByClass, firstDivergingPass{mapId,worker,passIndex,callIndex,field,technique}, mapsCompared, mapsDiverged, maxDepthDelta, firstDivergentTexel, capturePath }` and a **`run` action** ("render N frames in `VALIDATE`, then report"). Today those stats are log-only (cpp:1012-1025) and the tool returns just `{mode,hooksInstalled}` — this is the specific gap called out across all four analyses.
- **Rerunnable gate script** `tools/shadow-parity.ps1` (+ `.sh`) drives the existing devbench scenario API (`127.0.0.1:8920`, `CS_AUTOLOAD_SAVE`): for each of the 3 venues → `load save` → set `VALIDATE` → run N frames **in motion** → assert `passesDiverged==0 && mapsDiverged==0 && maxDepthDelta==0`. Exit non-zero on any divergence with the pinpoint. Parity is trusted only after 0-divergence across venues in motion for **≥2 sessions** (the intermittency rule).
- **Future broken pass:** any later edit to a replica pass (or a threading regression) that changes a pass's command stream *or* its depth output trips Level-1 `firstDiff` or Level-2 depth-delta on the next `shadow-parity.ps1` run, naming the exact map + pass + call + field. That is the standing regression gate the task requires.

- Raise `T` to `clamp(cores−4, 2, 6)`; cost-weight the partition by index-count (skinned weighted higher) to balance a dominant cascade across maps.

- **Optional phase 4 (only after N-way `REPLACE` is stable):** graft #2's intra-map sub-splitting — split a dominant cascade at technique/geometry-group boundaries into command-list *segments*, validated with the tolerant order-equivalence variant of `DiffWindows` (not strict tuple identity, because a segment boundary forces a redundant `BeginPass`).

Re-gate (G1-style structural+output across venues in motion, ≥2 sessions) at every widening.

## 4. Top risks and how the validation layer retires each

| # | Risk | How validation retires it |
|---|------|---------------------------|
| 1 | **CS-replicated `SetDirtyStates` diverges from the engine flush for one dirty bit** → silently mis-binds *every* threaded pass. | It is exercised at **G1 single-threaded** against the byte-exact `DiffWindows` (the same gate that already proved 1.1M/0). Any bit mismatch trips `firstDiff` on an `OMSetRenderTargets`/`RSSetViewports`/topology tuple, naming the field — *before* any thread exists. |
| 2 | **Shared `BSShader+0x90` flag / `geom+0x108` LOD / `SubIndexPreDraw` segment coalesce race across cascades** — intermittent, motion-only (exactly the failure the memory warns stills can't catch). | These are de-shared to `thread_local` shadows in step (a) and the **motion, multi-venue, ≥2-session** structural+output gate is specifically designed to surface cross-cascade races. Sub-index/skinned stay on the serial remainder until their coalesce/upload is replicated into worker-local scratch (G4), so they cannot corrupt parity before they are proven. |
| 3 | **Concurrent live-context capture** (`PersistentBindings.Capture(immediate)`) data-races the render thread. | Retired structurally by **Gate G2**: standalone re-derived bindings, no `Get*` in the scope, re-verified to still pass G1 before any second thread. |
| 4 | **`ExecuteCommandList` ordering / interleave nondeterminism** that the command+data hash cannot see. | This is precisely why **Level-2 output readback** exists: per-slice depth diff vs the vanilla real atlas catches any GPU-side interleave effect and pinpoints the map. Replay is keyed to `mapWorkList` (canonical engine order), and a reorder bug shows as a depth delta on the affected slice. |
| 5 | **Engine TLS AVs on bshoshany worker threads** (`+1896`/`+10752`). | G1's single-worker static-path compare proves those two writes are inert for the covered static path (elidable); skinned coverage only advances in G4 *after* a per-worker engine TLS block is installed and re-gated. |
| 6 | **Per-worker ring privatization wrong** (bone-CB / dyn-VB) → skinned casters corrupt each other's palettes. | Skinned maps do not go parallel until G4; when they do, the per-slice output diff + per-pass `kMapDiscardData` byte-hash (which already validates dynamic-VB/bone-CB *content*) catch any ring aliasing as a data-hash `firstDiff` or a depth delta. |
| 7 | **Net FPS is flat or negative** (paced DLSS-G regime; the record win requires a render-thread bottleneck; the ordered `ExecuteCommandList` + re-establish tail is serial Amdahl overhead). | Not a *correctness* risk but a *ship* risk: measured with the `rtprof` harness at **every** gate (G3 onward), widening is blocked if net-negative or within noise. The plan can ship the *validated single-context replica* (a proven RE asset) even if MT shows no FPS win. |
| 8 | **DXVK re-serializes concurrent `FinishCommandList`** on its shared discard/memory allocator locks (the ntdll-hotpath / parallel-shader-setup notes show that allocator already contends), capping the perf win. | Same as #7 — measured, not assumed; parity holds regardless. If capped, phase-4 sub-splitting and per-worker ring pools are the levers, each re-gated. |
| 9 | **Accumulator-walk or per-map camera-CB RE is subtly wrong** (wrong pass order, wrong shadow view-proj). | G1 catches it two ways at once: a wrong pass order is an immediate structural size/`firstDiff` mismatch; a wrong camera CB is a wrong depth everywhere → Level-2 `maxDepthDelta` across the whole slice. Both fire single-threaded before threading. |
| 10 | **SE-1.5.97-only** (all offsets hardcoded; AE/VR unmapped). | Unchanged scope; `InstallHooks` bails on AE exactly as `UtilityPassReplica`/`ShadowDeferred` do today. The validator's REST gate makes a future AE port's parity a one-command check rather than a manual audit. |

**Bottom line:** the plan makes the *standalone per-map replica driver* the single keystone, proves it map-identical to vanilla at **both** structural and output level single-threaded (G1) — which is also the exact artifact the output-parity gap in every analysis demands — then reuses that identical driver + validator across 2→N private deferred contexts, with the `shadow-parity.ps1` REST gate standing as the rerunnable regression check that names any future deviating pass down to the call and field.

## Candidate architectures considered


### Per-Shadow-Map Deferred Fan-Out (map-granular workers, replica-path record, ordered ExecuteCommandList)  (effort: high)
- **Threading model:** UNIT = one invocation of BSShadowLight::RenderShadowmap 0x141305610 = one (DS-target, slice) shadow map: a sun cascade (DS target 2, slice i), a volumetric-lighting pre-pass slice (target 3), a focus slice (target 4, slice>=4), or a local-light face (target 4 pool slice). Per frame N is small and coarse: <=~4 sun cascades + optional equal VL slices + focus + <=4 lights from CalculateActiveShadowCasterLights => N~4-16 maps, each hundreds-to-thousands of draws. SEAM: keep the ShadowDeferred detour on ShadowSceneNode_RenderAllShadowmaps 0x1412E3480, and additionally detour RenderShadowmap 0x141305610 as a PLANNING interceptor: let the engine per-light Func10 loops (directional 0x141324C30 / frustum 0x14132D040 / parabolic 0x14132E4E0) run serially on the render thread ONLY to perform the deterministic lazy pool-slice allocation (free-slice bitmask dword_141E10538) and to snapshot each map's resolved params BY VALUE {camera=desc+64, accumulator=desc+72, target=desc+84, slice=desc+88, renderFlags=a4} into an ordered mapWorkList (call order == canonical map order; capture by value because directional reuses desc[i] and rewrites +84 between the VL and main loops); the detour returns WITHOUT drawing. THREADS = min(N_maps, maxWorkers) from a dedicated BS::thread_pool (the same pool type ParallelShaderSetup already owns). Ship maxWorkers=2 first (each heavy sun cascade to its own worker, cheap VL/focus batched, skinned/sub-index-heavy maps stay serial on the render thread), then scale to min(N_maps, hardware_concurrency - reserved) capped ~4-6 so the render thread and any concurrent ParallelShaderSetup pool keep core headroom. Each worker owns ONE private ID3D11 deferred context and records its map(s) via the UtilityPassReplica REPLICA path (ReplicaRenderPassImmediately -> DrawTriShapeReplica -> DrawIndexed, which walks the map's accumulator itself), producing an ID3D11CommandList (FinishCommandList(FALSE)). ORDER/EXECUTE: the render thread blocks on a completion latch for all workers, then replays strictly in map order: for m in 0..N { immediate->ExecuteCommandList(cl[m], FALSE); }. Disjoint DSV slices mean map outputs never alias, so map-order FALSE-replay reproduces vanilla's serial submission deterministically; after replay, re-establish the immediate context exactly as the current single-scope teardown (PersistentBindings.Apply, memcpy S snapshot back, sflags[0]=0xFFFFFFFF). INCREMENTAL: Phase 0 = replica path drives the WHOLE shadow render serially on one deferred context from the mapWorkList + ordered replay (de-risk the seam, reuse ShadowDeferred verbatim); Phase 1 = 2 workers, static-TRISHAPE maps parallel, with validation; Phase 2/3 add skinned+sub-index coverage and scale to N.
- **State isolation:** The single-scope "swap one global, run engine code" model cannot go N-way (there is exactly one 0x143027EA0 to swap), so per-map MT is built on the REPLICA path, which issues every D3D call itself and can therefore target a per-worker context + per-worker state; ShadowDeferred remains the single-thread fallback and the origin of the record->ExecuteCommandList + PersistentBindings mechanics. Per-worker privatization of the phase-1 race surface: (1) DEFERRED CONTEXT - K private contexts created once, reused (D3D11 contexts are not free-threaded). (2) RendererShadowState dirty block (0x5D8 @ 0x143027EB0) - each worker gets a private 0x5D8 block; DrawTriShapeReplica writes S_vertexDesc(+0x340)/S_topology(+0x358)/stateUpdateFlags into the WORKER block, and SetDirtyStates is REPLICATED in CS (fully RE'd in the dossier: bit1 RT/DSV+pending-clear+OMSetRenderTargets, bit2 viewport RSSetViewports, raster/blend/IL/topology) reading the worker S and flushing to the worker context. This is the keystone - the fixed-address engine SetDirtyStates 0x140D705B0 is never called on a worker. (3) Cross-pass caches technique 0x1403283BA4 / shader 0x1403283BA8 / material 0x143490BB0, shadow geom token 0x1401E10660, subIndexWholeDraw 0x1430243B0, debugTechnique - per-worker scalars (pure change-detection the replica already owns). (4) DYN-VB ring (buffers 0x143025F18[0..2] + state 0x143025F30) - per-worker private VB + ring state (K x ShadowDeferred's single privateDynVB), DISCARD-mapped at offset 0 on the worker context (deferred-legal). (5) BONE-CB ring (cursor 0x143027A00 + four 3840B CBs) - per-worker cursor + private CB set. (6) THREAD-LOCAL REDIRECTION: the fixed 0x143027EA0 cannot be made per-thread, so the worker path never reads it - the replica binds its own context explicitly; recorder infra becomes thread_local (per-worker g_sink/g_openMaps[8]/g_filterCs and K out-of-module stub trampolines, since the cpp:57 "one slot suffices" note depends on single-threaded compare, indexed by a thread_local worker id). ### Chunked Pass-Tape Recording on Per-Worker Deferred Contexts with Thread-Local Engine-State Redirection (per-pass-batch)  (effort: very-high)
- **Threading model:** FAN-OUT SEAM = collect, don't render inline. Keep the existing RenderPassImmediately detour (0x141308440), but under CS_SHADOW_MT and inside the ShadowDeferred scope (RenderShadowmaps 0x1412E3480) the detour does NOT render. It appends a PassRecord {BSRenderPass*, technique, alphaTest, renderFlags, passEnum, geometry, coverable=CanReplicate(), costWeight=indexCount} to a per-frame contiguous "pass tape" vector, in exact engine-walk order, on the render thread. Vanilla ordering is preserved deterministically because the engine's own serial batch walk still fills the tape.

UNIT OF PARALLEL WORK = a contiguous half-open range [lo,hi) of the pass tape (a "chunk"). Deliberately NOT per-light / per-cascade: the flat tape spans all sun cascades + point/spot maps, so one dominant sun cascade (which per-light or per-shadow-map threading would strand on a single worker) is split across every worker — that is the load-balance advantage, paid for with the ordering + shared-state complexity handled in stateIsolation.

PARTITIONING: after the tape completes at scope end, split into T contiguous chunks of ~equal cumulative costWeight (index-count proxy, skinned weighted higher). Snap chunk boundaries to technique/geometry-group boundaries (the batch renderer already groups passes by technique/geometry-group, so groups are contiguous) so a given BSShader's SetupTechnique/RestoreTechnique pair lives entirely inside ONE worker. Uncoverable passes (CanReplicate==false: STENCIL_ABOVE_WATER, needs-custom, dynamic bone-setter skin, non-trishape) cannot run on a worker; they become hard chunk boundaries and are rendered on the render thread as an "engine remainder" interleaved at their tape positions.

THREAD COUNT: T = clamp(hardware_concurrency − RESERVE, 2, CAP); RESERVE ≈ 4 (render thread + DXVK CS/submit + present + game sim), CAP ≈ 6 (ExecuteCommandList tail + build overhead give diminishing returns). Independent of light count. Workers come from the existing bshoshany BS::thread_pool; N deferred contexts are created once at Setup and reused every frame (ShadowDeferred is the single-context precedent).

ORDERING + EXECUTION: each worker i records its chunk into its own ID3D11CommandList via its private deferred context and FinishCommandList(FALSE) concurrently. Barrier (pool wait). Then, single-threaded on the render thread, ExecuteCommandList in ascending chunk order (cl_0, cl_1, …) on the immediate context, interleaving the engine-remainder passes at their recorded tape positions. Because chunk order == tape order == vanilla walk order, GPU submission order is byte-for-byte the vanilla serial order — that is the whole point of contiguous chunking. RestoreContextState=FALSE (DXVK guideline) leaves the immediate context cleared, so re-establish it exactly as ShadowDeferred does (re-apply persistent bindings + viewport/scissor + force S dirty). The RECORD phase is parallel; the EXECUTE + re-establish phase is the serial Amdahl tail.
- **State isolation:** Per worker, created once at Setup and reused per frame:
1) PRIVATE DEFERRED CONTEXT (CreateDeferredContext). D3D11 mandates distinct contexts for concurrent command-list build; DXVK supports this.
2) PRIVATE 0x5D8 RendererShadowState DIRTY BLOCK — a per-worker byte buffer. Each frame memcpy the pre-scope engine snapshot (from 0x143027EB0) into it, then force sflags[0]=0xFFFFFFFF so the chunk's FIRST pass fully re-establishes RT/depth/raster/blend/IA/topology on the cold context (the same trick ShadowDeferred uses at scope entry).
3) THREAD-LOCAL GLOBAL REDIRECTION. The engine reads the dirty block, caches, rings and context from FIXED absolute addresses (0x143027EB0, 0x1403283BA4/A8, 0x143490BB0, 0x143025F18/F30, 0x143027A00, 0x143027EA0), so a per-thread copy is inert unless the READS are redirected. Two tiers:
   • Calls the replica itself issues (it already reimplements the pass body ReplicaRenderPassImmediately + draw leaf DrawTriShapeReplica): (a) all D3D11 goes through a PER-WORKER out-of-module stub slot whose target is that worker's deferred context — g_stub/g_stubSlot/g_stubActive MUST become thread_local; the source comment at UtilityPassReplica.cpp:57 explicitly says one slot suffices ONLY because compare is single-threaded. (b) SetDirtyStates is REPLICATED in CS reading the worker's thread-local S (DrawTriShapeReplica already writes S_vertexDesc/S_topology/S_stateUpdateFlags then EngineCall's SetDirtyStates — swap that EngineCall for a thread-local-S flush). (c) technique/shader/material cache scalars, shadow-geom token (0x1401E10660), subIndexWholeDraw (0x1430243B0) and debugTechnique become thread_local variables the replicated body reads/writes.
   • Engine VFUNCS the replica still delegates to — SetupTechnique(vf2)/RestoreTechnique(vf3)/SetupMaterial(vf4)/SetupGeometry(vf6)/RestoreGeometry(vf7)/skin Render(vf37) — read those same fixed globals INTERNALLY (SetupGeometry writes the geom token; RestoreTechnique reads token + the +0x90 flag; skin Render re-reads bone ring/cursor/context). This is the residual RE burden and the gate on full N-way parallelism: each must be re-implemented in CS against thread-local state. Until replicated they stay on the SERIAL engine-remainder side (see incremental path).
4) PRIVATE DYNAMIC-VB RING: own privateDynVB buffer + thread-local ring cursor. Concurrent WRITE_DISCARD map of DISTINCT buffers on DISTINCT deferred contexts is legal (the illegal case is mapping ONE buffer twice). The DynVBAllocHook (id 75484) becomes per-worker (keys off thread-local scopeActive + thread-local context).
5) PRIVATE BONE-CB RING: own 4 dynamic bone CBs + thread-local cursor. This is ShadowDeferred's known gap (it only saved/restored the shared cursor at 0x143027A00); MT REQUIRES private bone buffers or skinned casters corrupt each other's palettes.
6) SHARED-OBJECT WRITE HAZARDS a global-copy cannot fix — redirect to thread-local scratch: BSShader+0x90 technique flag (one instance across cascades) — the technique-group partition snap keeps a shader's Setup/Restore in one worker, and the replicated SetupTechnique/RestoreTechnique read/write a thread-local flag shadow; geom+0x108 LOD and SubIndexPreDraw segment-coalesce on the SHARED geometry (same mesh drawn into multiple cascades) — the replica already owns those writes (DrawTriShapeReplica stamps geom[0x108]; SubIndexPreDraw is reimplemented), redirect to thread-local scratch; engine TLS via 0x143497408 (+1896 memctx tag, +10752 skin accumulator) — a bshoshany worker has no engine TLS block so these AV, so the replicated skin path keeps them thread_local (or each pool thread installs an engine-compatible TLS block).
7) THREAD-LOCAL scopeActive + active-context so the Hooks.cpp BeginTechnique/SetVertexShader/SetPixelShader gates forward engine-original shaders onto the CORRECT worker's context (the header already flags promoting scopeActive to thread_local).

REUSE OF PERSISTENT/STANDALONE BINDINGS: PersistentBindings (VS b12 camera CB + samplers, all 6 stages, bound once/frame outside the dirty system) is read-only per frame — capture ONCE on the render thread at scope entry, then Apply the SAME snapshot to EACH worker's deferred context before its chunk (the "safe to share read-only snapshot"). ### Per-shadow-map record-then-replay job graph with private RendererShadowState and a seam-inserted structural+output validator  (effort: very-high)
- **Threading model:** UNIT OF WORK = one shadow map (one directional cascade, or one point/spot light's map). The driver DrawWorld::RenderShadowmaps (0x1412E3480) whose body IS the shadow-caster-light loop is the fan-out seam. Each map is an independent depth target with its own culled caster list, viewport, and view-projection; maps write disjoint atlas regions, so there is no inter-map data dependency — the ideal job boundary. A worker records ALL BSUtilityShader caster passes for its assigned map(s) into ONE command list. (Fine-grained sub-map chunking is deferred: passes within a map share the technique/material change-detection caches, so a chunk boundary forces a redundant BeginPass — correct but not byte-identical, so it needs the tolerant order-equivalence check rather than strict tuple identity; per-map partition preserves the engine's exact intra-map pass order and caching, so byte-identity holds.)

THREAD COUNT = min(shadowMapCount, hardware_concurrency - 2), reserving the render thread and DXVK's submission/CS thread; capped at the frame's live map count (typically 3-4 directional cascades + a few object maps). Reuse (or clone) the bshoshany BS::thread_pool already owned by ParallelShaderSetup (ParallelShaderSetup.h:135). Ship at 2 workers first, then raise to per-map N.

JOB GRAPH = pure fan-out/join. STAGE 1 (parallel record): each worker owns a PRIVATE ID3D11 deferred context (D3D11 contexts are not free-threaded — one per recording thread, created once at Setup like ShadowDeferred.cpp:405, but N of them). For its map it records: RSSetViewports/Scissor for that map, OM bind of the map's depth target, ClearDepthStencilView, then the byte-exact replica stream (ReplicaRenderPassImmediately, UtilityPassReplica.cpp:814) for each covered caster pass against its PRIVATE dirty block, then FinishCommandList(FALSE) -> ID3D11CommandList*. Workers never touch the immediate context. STAGE 2 (serial replay): back on the render thread, after pool.wait_for_tasks() joins, ExecuteCommandList each finished list on the immediate context in CANONICAL ORDER — the exact order the engine's serial loop iterated the maps (captured at partition time as a (mapType,mapIndex) sort key, NOT job-completion order), so replay is deterministic though jobs finish out of order. RestoreContextState=FALSE per DXVK guidance, then re-establish persistent bindings + pre-scope viewport/scissor + forced-dirty exactly as ShadowDeferred.cpp:354-373 does today.
